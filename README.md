# Agent Benchmark 1GB

**Статус:** проектирование методики; выполнение не начато  
**Версия документации:** 0.1 (25 октября 2026)  
**Язык:** русский

## Идея проекта

Воспроизводимо сравнить самостоятельные AI-агенты на ограниченном виртуальном сервере **Oracle Cloud Always Free — VM.Standard.E2.1.Micro** (ориентир: 1 ГБ RAM, ограниченный CPU, x86-64), определить, какие из них подходят для круглосуточной работы с внешними LLM, и выбрать агент по балансу функциональности, потребления ресурсов, устойчивости и безопасности.

**Ограничение на текущий этап:** **никаких установок, запусков, изменений конфигурации или расходов**. Здесь только проектная документация.

## Кандидаты (текущий согласованный набор)

1. ZeptoClaw
2. ZeroClaw
3. Picobot
4. PicoClaw
5. PennyClaw
6. Moltis

NullClaw не включён в выбранную шестёрку. Возможные кандидаты второй волны: NullClaw, MicroClaw, Hermes Agent. Включение требует отдельного решения.

> Названия проектов могут быть неоднозначны. Перед испытаниями необходимо зафиксировать точные URL репозиториев, лицензии, релизы/commit SHA, официальную процедуру установки и поддержку Linux x86-64. Неиспытанные возможности не считаются подтверждёнными.

## Что получим

- Сопоставимые данные по памяти, CPU, диску, запуску и ошибкам.
- Проверку стандартного API-взаимодействия и 2–3 агентных задач.
- Оценку полезных функций: инструменты, MCP, память, расписания, Telegram, секреты/права доступа.
- Матрицу пригодности для Oracle 1 ГБ и рекомендации с оговорками.
- Отчёт с воспроизводимыми конфигурациями, логами и исходными метриками без секретов.

## Принципы

- **Один агент в один момент времени** на одинаковой машине.
- Сначала проверка совместимости на Mac, затем реальное измерение на Oracle; результаты macOS не включаются в сравнительные цифры Linux.
- Сравнивать **два профиля**: базовый (без инструментов) и прикладной (общий набор доступных функций). Отсутствие функции отмечать отдельно.
- Внешний API модели стандартизирован: сначала mock-LLM с фиксированными ответами, затем один и тот же реальный провайдер/модель.
- Измерять как **сам процесс агента**, так и **полную стоимость его сервисного окружения**; не путать бинарник с расходом RAM при работе.
- Не выполнять непроверенный сторонний код с доступом к основной инфраструктуре и секретам.

## Последовательность работ (план, не выполнение)

1. Зафиксировать репозитории, версии, требования и лицензии.
2. Сделать инвентаризацию существующего Oracle (без изменений) и проверить ресурсный запас.
3. Спроектировать эталонные сценарии, mock LLM, сбор метрик, контейнерные лимиты.
4. Проверить установку и API на Mac/Linux-тестовом окружении.
5. Протестировать каждого кандидата по одному на Oracle, сохраняя результаты.
6. Провести длительный тест 24 ч только для 2–3 финалистов, если тестовая VM доступна без ущерба существующим сервисам.
7. Подготовить финальный сравнительный отчёт и рекомендацию.

**Точка согласования перед любыми действиями:** где проводить измерения (изолированная VM или действующая), доступный объём RAM/диска, способ выдачи тестовых API-ключей, разрешённые инструменты и лимит платных API-вызовов.
