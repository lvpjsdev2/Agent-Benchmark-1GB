# Концепция проекта

## 1. Вопрос исследования

Какой из шести выбранных AI-агентов способен стабильно работать на Oracle E2 Micro (1 ГБ RAM) и давать нужный набор инструментов с минимальным расходом ресурсов и приемлемым уровнем безопасности?

Не следует выбирать победителя только по числу мегабайт в простое: решает пригодность к реальным задачам.

## 2. Основные варианты использования

- Доступ к персональному агенту через мессенджер или CLI/WebUI.
- Использование внешних LLM (возможен прокси FreeLLMAPI, **но для первого цикла тестируем без него**, чтобы исключить дополнительную переменную).
- Простые инструменты: чтение/запись файлов в отдельной рабочей папке, безопасные shell-команды.
- При наличии реализации: MCP, долгосрочная память, расписания и навыки.
- Работа 24/7 без локального инференса и браузера на первом этапе.

## 3. Условия и ограничения

- Целевой сервер: Oracle Cloud Always Free VM.Standard.E2.1.Micro, Linux x86-64, 1 ГБ RAM. Конкретные ОС, свободная память, swap, диск, ядро, CPU quota и фоновые службы записываются непосредственно перед измерениями.
- Запас RAM может быть существенно ниже 1 ГБ из-за ОС/демонов. Не запускать одновременно с важными рабочими сервисами без отдельного разрешения.
- GPU нет; локальные модели не являются частью исследования.
- Внешние API и сетевые задержки могут изменяться; для измерения накладных расходов использовать mock-LLM.
- Стоимость запросов к платным API заранее ограничить бюджетом и квотами.

## 4. Scope

### Входит

- Проверка установки, запуска и доступности стандартного чата.
- Статистические измерения RAM, CPU, диска, стабильности.
- Проверка инструментария и поддерживаемых интеграций.
- Документирование версий, опций, ограничений и отказов.

### Не входит в первую итерацию

- Браузерная автоматизация, поиск в Интернете из агента, массовые MCP-серверы, локальные LLM.
- Реальные личные документы, подключение почты, финансов и production-секретов.
- Нагрузочное тестирование высокой конкурентности, атаки на защиту, тесты качества разных LLM.
- Развёртывание всех агентов параллельно.

## 5. Гипотезы

- H1: хотя бы три агента запускаются и выполняют базовый диалог без OOM на свободной VM 1 ГБ.
- H2: расход RAM на реальные инструменты намного сильнее различается, чем RAM в простое.
- H3: более тяжёлый агент может оказаться предпочтительнее компактного за счёт MCP, безопасности, управления секретами и стабильности.

Все гипотезы требуют измерения; не считать их фактами заранее.

## 6. Критерии успеха

Минимальное техническое соответствие:

1. Запуск на целевой Linux x86-64 без неподдерживаемых библиотек/архитектуры.
2. 30 последовательных запросов через mock без неконтролируемого падения и OOM.
3. Хотя бы одно типовое полезное действие на внешней LLM (если агент предназначен для инструментария), либо явная пометка «чат без инструментов».
4. Нет необходимости отключать базовую защиту ОС, давать привилегированный Docker или помещать реальные секреты в небезопасные логи.

Предварительная цель по RAM: пик **полного сервисного окружения** не должен приводить к memory pressure/OOM при сохранении резерва ОС. Численный порог задаётся после инвентаризации фактически свободной RAM; не объявлять 1 ГБ доступным приложению.

## 7. Решение по итогам

Публикуем три победителя в отдельных категориях: «минимальные накладные расходы», «лучший функциональный компромисс», «лучший для постоянной эксплуатации». Одного абсолютного победителя определяем только при наличии явного превосходства.
