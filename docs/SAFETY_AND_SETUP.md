# Безопасность и предварительные условия

## Перед созданием стенда

**Никаких действий без отдельного согласования.** Не подключаться к серверу, не менять firewall, не устанавливать Docker/агентов, не создавать VM, не регистрировать платные API, не выдавать доступ к ключам на этапе документации.

Проверить (пока это чеклист, а не исполненные действия):

- [ ] Узнать текущую ОС, RAM/`MemAvailable`, swap, CPU quota, диск, список сервисов и свободные порты Oracle VM.
- [ ] Определить, можно ли остановить сторонние рабочие контейнеры; если нет, использовать другую тестовую VM/локальную Linux VM.
- [ ] Зафиксировать лимиты Always Free, в том числе возможные расходы за дополнительные ресурсы и исходящий трафик.
- [ ] Подтвердить официальные URL репозиториев и контрольные суммы релизов всех шести проектов.
- [ ] Решить, где расположен mock-LLM: лучше на Mac или отдельной машине; доступ только по защищённому каналу.
- [ ] Назначить максимальный бюджет API, rate limits и allowed models.
- [ ] Подготовить отдельные тестовые ключи с минимальными правами.
- [ ] Настроить автоостановку теста при OOM, потере SSH/health, росте CPU/RAM/диска и превышении бюджета.

## Изоляция

- Отдельный непривилегированный пользователь, тестовая рабочая директория и каталог временных данных; никаких личных файлов или SSH-ключей.
- Установка из закреплённых версий/образов, без автоматического обновления в ходе эксперимента.
- Docker: без `--privileged`, без mount `/var/run/docker.sock`, без host network, без доступа к корню хоста.
- Shell-действия только в тестовом каталоге; запрещены опасные сетевые, системные и административные команды.
- Локальный bind или защищённый SSH-туннель вместо публикации UI/API; Telegram не обязателен в тестах производительности.
- Раздельные секреты каждого кандидата; журналы не должны их раскрывать.
- Для исходного внешнего кода необходимо провести минимальный обзор install scripts и dependency provenance.
- Не считать Docker достаточной границей безопасности для недоверенного агента; предпочтительна выделенная VM.

## Контроль рисков

| Риск | Предотвращение |
|---|---|
| OOM и деградация системных служб | Один агент, memory limits, stop threshold, мониторинг `MemAvailable` |
| Платные вызовы модели | Mock-сначала, отдельный ключ, квоты, capped budget |
| Утечка ключей | Отдельные ограниченные токены, env/secret store, исключение логов |
| Изменения на основной VM | Отдельная VM или подтверждённое окно тестирования, резервные копии конфигов |
| Непроверенные бинарники | Закреплённые релизы, sha/digest, обзор скриптов |
| Несопоставимые измерения | Одинаковый host, повторные запуски, одинаковый endpoint |

## Решение перед стартом

Не начинать измерения до согласования: (1) конкретного хоста, (2) полного набора кандидатов, (3) тестового LLM/API, (4) разрешённых инструментов, (5) бюджета и порогов аварийного прекращения.
